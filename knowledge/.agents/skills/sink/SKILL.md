# sink — 沉淀

参数里有「复盘」就走复盘模式，否则走单条模式。规范以 Vault `AGENTS.md` 为准。`kb` = `python .agents/skills/kb/scripts/kb.py`。

## 先检查实际采用记录

按 Vault `RSI.md`，检查本任务真正采用的卡片路径、revision、稳定 task ID 和可观察结果。对有结果的记录先执行 `kb feedback <path> --task <id> --revision <hash> --outcome helpful|noop|misleading --reason "具体影响" --evidence "证据定位"`。同一任务续接沿用 ID；无引用不造记录，缺结果就记待评价，不阻断新知识沉淀或 handoff。仅检索命中不结算。

三个独立任务的 helpful 只达到复核候选；检查证据、反例和边界后才在符合条件的反馈中加 `--confirm-review`。不因总分高而升级原始 evidence，不给本轮刚写的规则打自证分。

## 单条模式

1. **挑经验**：从本次会话里找踩过的坑、验证有效的做法、用户拍板的口径。门槛是说得出下次在什么任务里会用到；项目进度、一次性修复、账号和密钥不收。
2. **查同类**：每条先运行 `kb find "<一句话规则>"`。命中同主题、同对象的卡，就按 AGENTS.md 的「吸收」规则并进去；没有就 `kb new lesson <英文-slug> --title <标题>`。
3. **填卡**：已有卡原地整合当前有效方案，过时步骤保留理由和原始出处后移出当前路径；护栏去重并限定适用范围，变更记录每次一行。`summary` 写一句可执行规则；`tags`；`when` 写任务说法或症状，可以带错误码；`not_when`；`evidence`；`source`。正文写做法、为什么、边界。
4. **收尾**：运行 `kb build`，再 `git add -- <本次修改的文件> && git commit -m "sink: <摘要>"`。
5. **汇报**：分新建、合并、待用户拍板（更优、冲突）三类列出。

## 复盘模式

1. **收集**：本次会话，加上项目的交接链和 README、`git log`。项目用了 handoff 时：`handoff ls` 看交接链；最新交接的 `brief`（目标、验收、被否决的方案 → 档案的关键决策）和 `state`（决定与证据）；`handoff show <编号> history` 是逐次账本。没有 handoff 就读 HANDOFF 文档。只用能核实的信息，数字注明来源。
2. **找档案**：`kb find "<项目名>"`。已有档案就更新；没有就 `kb new playbook <项目-slug> --title <项目名>`。
3. **填 8 节**：保留档案八节，更新当前决策与方案，避免文末追加另一份总结。读取 handoff 的知识引用与异常投影，再回原始输出核实；只有具有复用价值、根因有证据的排障才独立为 lesson，项目档案只放链接。`when` 写「做类似项目时用户会怎么说」；踩坑的每一条按单条模式写成经验卡，档案里只放 `[[卡片]]` 链接。
4. **收尾**：`kb build`，提交，汇报。

## 预算与收尾

对每张变更卡执行 `kb lint <path>`，超标时精简当前结论、去重护栏或拆独立主题，原始证据留在 source/Git。然后 `kb build`。反馈造成的隔离也需要 build 更新路由；修复后以新版本重新评估。只暂存本次文件，不包含用户其他未提交工作。
