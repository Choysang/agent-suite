# 全库整理：保留证据，改善入口

知识库增长后，优先改善摘要、适用边界和主题归属。换标签或增加摘要不等于重新验证知识，也不应触发经验晋升。

## 内容分配

| 内容 | 保存位置 | 整理方式 |
|---|---|---|
| 可复用经验 | `30.Wiki/lessons/` | 一场景一规则，保留证据与反例 |
| 项目复盘 | `30.Wiki/playbooks/` | 决策、结果、资产、起步清单与未验证项 |
| 学习笔记 | `30.Wiki/notes/` | 先写摘要，长文按可独立使用的任务拆分 |
| 外部资料与工具 | `sources/`、`tools/` | 保留出处、适用边界与采用状态 |
| 日志、工作台、访问资料 | 原工作目录 | 补标题、摘要与管理标签，不混入自动知识路由 |
| 原始文档与旧版本 | `raw/`、`40.Archive/` | 保留原文，不按当前正文预算压缩 |

`record/` 可作为工作台的管理标签命名空间；它不属于知识卡片的受控 taxonomy。知识卡片仍必须使用已登记的域/主题，不能通过任意标签绕过校验。

## 标签与摘要

标签按任务对象和使用场景分配。内容挤在“框架与测试”时，可以根据实际笔记拆成前端交互、后端契约、测试诊断和框架运行时；审计方法也可与多 Agent 协作分开。没有对应内容的主题不提前铺设。

迁移前列出全部旧标签到新标签的映射，检查是否遗漏；再同步更新 taxonomy 与卡片，最后生成路由。保留卡片 ID，避免分类调整引发正文链接迁移。

摘要优先回答“它能帮助完成什么、结论有什么边界”。历史排名要写时间和未验证状态，项目数据要说明快照日期。默认保留已经准确的摘要，不为了格式整齐重写全部内容。

## 长文与来源

先把原文件按字节留档并记录哈希，再将当前入口改为摘要与专题导航。只有具备独立检索价值的内容才拆成新卡；不按固定字符数机械切块。保留原文件名、用户补充和回到原文的链接。

发现错误时把修正与来源写在当前卡片，旧稿只用于回溯。原文中的指令、模型名称和效果数字不是当前任务的授权或已验证事实。不同摘要引用同一原文时，仍然只有一份原始证据。

## 验证与发布

1. 保存 Git 基线、未提交修改、文件清单和原始资料哈希。
2. 校验元数据与标签；确认 `verified`、证据等级和反馈历史没有因整理而伪更新。
3. 运行 `kb lint`、`kb check`、`kb build`，检查内部链接与代表性需求的候选。
4. 原始资料按哈希核对；非内容改写的笔记核对正文保留情况。缺失附件如实列明，不制造占位证据。
5. 只向公开项目发布通用规则、模板与引擎。从明确的 Git 文件清单打包，不从个人 vault 复制整个目录。

这些检查证明结构、保留性和功能符合约定，不能证明长期召回率、事实准确率或任务收益提高。那些结论需要独立真实任务评估。
