# 模块四：串联全流程的每日开发闭环 (真实案例实操)

> 看看三者的联合体如何在普通开发者的一天中无缝运转，实现“越用越聪明”的正向飞轮。

---

## 🌅 上午 09:30 · 晨间开工与认知就绪

你打开终端，唤醒你的 AI 助手（例如 Claude Code 或 Codex）。

1. **你输入**：
   > “开工，今天有什么任务？”
2. **AI 的动作**：
   - 触发 `daily` 技能，读取 `50.Daily/TODO.md`；
   - 自动在常驻上下文中加载 **准则（宪法）** 与 **`ROUTER.md`（知识库 L0 路由）**；
   - AI 汇报：
     > *“早上好！今日待办：1. 重构支付回调接口；2. 修复订单高并发死锁。已为您就绪相关开发规范。”*

---

## ⚡ 上午 11:00 · 精准局部编码与经验沉淀

在修复订单死锁的过程中，你和 AI 排查了整整 40 分钟，最终发现是某条 SQL 的索引失效导致行锁升级成了表锁。

1. **你输入**：
   > “问题搞定了！沉淀一下刚才的排查经验。”
2. **AI 的动作**：
   - 触发 `sink` 技能；
   - 从刚刚的排查对话中提炼出精确信息：
     - `title`: MySQL 联合索引最左匹配失效导致行锁升表锁
     - `summary`: 订单查询必须显式指定覆盖索引，避免死锁
     - `when`: 遇到高并发订单更新报 `Deadlock found when trying to get lock`
     - `not_when`: 单机 SQLite 或低频后台批量更新任务
     - `evidence`: 实测
   - 写入一张 `lessons/mysql-deadlock-covering-index.md` 经验卡；
   - 运行 `kb build` 重新编译路由。
3. **结果**：全团队从此刻开始，永久免疫这个隐蔽 Bug！

---

## 🔄 下午 15:30 · 会话接力 (换模型 / 换窗口无损接力)

下午的任务是重构整个支付网关。在这个过程中，你已经连续执行了 50 多轮对话，当前模型的上下文窗口快要打满了，响应开始变慢；而且你想换用推理能力更强的模型（比如换成更擅长复杂算法的模型）来写核心状态机。

1. **在老窗口输入**：
   ```text
   /handoff
   ```
2. **老 AI 的动作**：
   - 提取真实进展与现场代码差异；
   - 整理出：
     - 已完成：微信支付 V3 验签通过（单测全绿）；
     - 已否决弯路：异步轮询方案（因并发延迟高已否决）；
     - 下一步：实现支付宝公钥证书模式状态机；
   - 将快照封存在 Git 专属空间 `refs/handoff/8`；
   - 终端输出：
     > *已封存 #8 · payment-gateway · 下一步：实现支付宝公钥证书模式状态机*
     > *接手方式：在任意新会话中输入 /handoff 8*

3. **在新窗口（全新会话/更强模型）直接输入**：
   ```text
   /handoff 8
   ```
4. **新 AI 动作**：
   - 秒级载入 `#8` 号快照；
   - 终端输出：
     > *接手成功！现场代码测试全绿。无需背景介绍，我立即开始编写支付宝证书状态机。*
   - **零废话、零 Token 浪费，直接无缝动工！**

---

## 🌙 晚上 18:00 · 项目收尾与复盘

功能全部开发完成，所有测试全绿通过。

1. **你输入**：
   > “支付网关重构完成了，复盘一下这个项目。”
2. **AI 的动作**：
   - 触发 `sink 复盘`；
   - 自动汇总本次里程碑涉及的代码变更与刚才的 `#8` 号交接快照；
   - 生成 `playbooks/payment-gateway-refactor.md` 项目档案：
     - 包含项目画像、关键技术决策、踩坑链接、下次起步清单；
   - 运行 `kb build` 重新生成全局路由。

---

## 📈 终局价值：认知资产的自我复利

这就是三者结合的威力：
- **准则** 保证了 AI 始终保持专业工程纪律，改动精准克制；
- **Handoff** 保证了无论开多少新窗口、换多少次模型，进度与现场永不丢失；
- **第二大脑** 保证了每次干活留下的智慧都能留存、复利，反哺下一次开工。
