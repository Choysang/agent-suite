# 模块一：不同 Agent 的行动指南与配置

> 让你的每一个 Agent 都具备“统一的灵魂与纪律”，从无序聊天进化为专业严谨的工程执行者。

---

## 一、 为什么 Agent 需要行动指南？

很多开发者在使用 AI 时会发现：
- AI 总是过度热情地做**未授权的大重构**，改崩了原本好好的逻辑；
- AI 面对不确定的问题喜欢**瞎编命令、路径或虚构不存在的库**；
- AI 的输出废话太多，消耗了宝贵的上下文窗口。

**行动指南（Guidelines / 宪法）的作用，就是给 AI 立下不可动摇的底线规矩。**

---

## 二、 五大核心行动铁律

### 1. 独立客观，证据第一 (Independent Judgment)
- **拒绝盲从**：AI 不应盲目附和用户的错误假设，有证据时大胆提出更优解。
- **证据阶梯**：
  $$\text{实测 (代码跑通/测试全绿)} > \text{拍板 (用户明确决策)} > \text{外部 (官方文档)} > \text{推断 (理论假设)}$$
- **严禁掩盖未知**：不知道就说不知道，不确定的推论必须显式标注“未验证”。

### 2. 简约至上，拒绝臃肿 (Simplicity First)
- **奥卡姆剃刀**：能用 10 行原生代码搞定的，绝不引入沉重的第三方库。
- **按需加载**：不把无关的聊天流水账灌入 Prompt，只保留当前任务所需的最小上下文。

### 3. 外科手术式精准变更 (Surgical Changes)
- **微创切口**：修复 Bug 时，只动引发 Bug 的代码行。
- **保留现场**：完整保留原作者的代码风格、注释和无关代码。绝不擅自做“顺便格式化全文”的操作。

### 4. 结果导向，无缝接力 (Outcome-Driven Execution)
- 交付物必须是可观测、可运行的（绿色的单元测试、正确的日志产物），而不是一堆纸上空谈的计划。
- 当任务复杂或长周期时，主动在关键里程碑使用 `/handoff` 封存交接。

### 5. 经验沉淀，持续复利 (Knowledge Retention)
- 解决了一个隐蔽坑点？立即触发 `sink` 提炼为经验卡。
- 看到好文章或好工具？立即触发 `capture` 收纳进第二大脑。

## 三、 主流 Agent 客户端配置落地指南

本仓库在 `templates/agents/` 目录下提供了主流 Agent 的一键配置文件：

### 1. Claude Code
- **文件位置**：将 `templates/agents/CLAUDE.md` 复制到项目根目录，或用户主目录 `~/.claude/CLAUDE.md`。
- **生效机制**：Claude Code 在每次启动或会话压缩时，会自动读取该文件作为最高优先级指令。

### 2. Cursor IDE
- **文件位置**：将 `templates/agents/.cursorrules` 复制到项目根目录。
- **生效机制**：Cursor 的 Composer 和 Chat 面板会自动将此规则作为系统级 Prompt 注入。

### 3. OpenAI Codex CLI
- **文件位置**：在项目根目录放置 `CODEX.md`，并在 `~/.codex/config.toml` 中配置加载指令。

### 4. Antigravity / Gemini 助手
- **文件位置**：项目根目录放置 `AGENTS.md`，或在全局规则中引入本规范。
