# 从研究到可维护实现

核对日期：2026-10-26。论文提供机制与实验结果，不直接证明本项目有同样收益。下面的“采用”是工程设计选择；任务质量和费用改善需另做成对实验。

| 研究 | 核心机制与边界 | 本项目落点 |
|---|---|---|
| [MedRGAG](https://arxiv.org/abs/2510.18297) | 用检索暴露的知识缺口引导生成补充文档，再联合选择精简上下文；生成文档仍可能有错。 | 采用“分项需求→检索→读原文判断覆盖→补查缺口”的流程，`find --need` 返回独立命中与去重候选。覆盖状态保留为待判断，生成线索不计入事实证据；没有声称完整移植医疗语料、多源配额或重排器。 |
| [CASD](https://arxiv.org/html/2609.26261v1) | 编码 Agent 对冻结轨迹做全局统计，再检查代表性案例并提炼规则。离线生成候选不依赖新 rollout，不等于部署后不用验证。 | 项目保存摩擦与原始证据；候选记录假设、Diff、版本和独立验收任务。规则提炼交给宿主，计算与记录交给 `kb experiment`。尚未实现自动全库轨迹采集，也不声称复现论文费用。 |
| [XYEval](https://arxiv.org/html/2609.23939v1) | 给原任务加入可信但错误的建议，保留原环境和验收，检查是否仍完成任务。提醒模型警惕 XY 问题只能部分缓解。 | Guidelines 区分目标、约束、偏好与诊断/方法假设；发现冲突用代码、日志或测试解释并继续工作。不能以“识别真实目标”为由覆盖用户明确选择，也不能只凭提示文本宣称已解决迎合。 |
| [RRSI](https://arxiv.org/html/2609.24972v1) | 对候选提出和选择施加约束：改动预算、历史证据、泄漏筛查、噪声与成本判断、无效组件剪枝。修改空间包括工具、记忆与子代理，并非只改提示词。 | 一次候选围绕可检验假设；冻结改动，保留失败提案；开发与验收分开；效果、成本、边界共同复核。最终留出集不应反复反馈给优化器。现有账本不实现自动搜索、噪声估计或自动晋升。 |
| [SoL-Pi 官方实现](https://github.com/NVlabs/SoL-Pi) | 动作融合、观测归档与按需召回、保留证据的日志归约、子任务边界压缩。它是 Pi 扩展，使用 Pi 公共接口，不能把这些开关照搬成 Codex 参数。 | 原始日志留项目，handoff 保留原话与来源；知识卡只保存可复用结论和定位；精简读取可返回全文，摘要不替代证据。宿主压缩、工具合并及模型路由按真实能力适配。 |

## 保持清晰的四个边界

1. **知识和证据**：Markdown 卡片是知识状态；原文、日志和 Git 是证据；路由、分数、摘要是可重建投影。生成的背景只作待验证线索。
2. **判断和动作**：宿主决定如何解题、选模型、拆任务；领域代码负责写入、版本、比较、冲突检查和错误传播。不用另一个模型替代可以精确计算的检查。
3. **通用流程和宿主适配**：共享规则描述目标和数据契约；配置路径、会话格式、hook、模型参数留在适配层。Team Agent 的角色职能、Codex 实现、外部服务发现及模型特例也按此分层。
4. **研究和发布**：提出候选、运行任务、独立复核、部署是不同事件。`ready_for_review` 只表示实验记录齐全；缺少运行版本和原始证据时仍须核对。不得拿单元测试数量当智能或泛化提升。

## 下一次改进如何执行

先从已有项目记录中抽取重复失败，统计分母和失败频率，再读代表性原始案例，排除偶发环境故障。为一个可复现机制写最小 Diff；用 [实验工作流](experiments.md) 固定任务、版本与指标。先执行开发任务，冻结后再做独立验收，保留失败结果和实际成本。评估不通过时保留原因，不持续叠加规则。

运行记录至少包含任务 ID、实际代码版本和工作区差异、开始/结束时间、退出状态、原始输出路径及文件哈希；模型信息只有宿主遥测可得时才填。人工记录与已核对运行证据要明确区分。模型自述、空日志或仅写版本名称都不是运行证明。

当前选择保持本地 CLI、Python 知识引擎、Git 交接协议和短指南。未来模型可改变任务规划与工具使用策略，而这些数据契约无需随模型名称重写。增加向量检索、独立调度器或多层评判模型前，先用实际任务证明现有能力缺口。
