# 模块二：各个会话交接手 (Handoff 跨会话与跨模型接力)

> 解决 Agent 开发中最折磨人的“上下文爆炸”与“换模型换窗口失忆”问题。

---

## 一、 为什么传统交接方式会失败？

很多开发者在长会话变卡或者要切换模型时，通常会这么做：
> “请你总结一下刚才我们聊了什么，我开个新窗口发给新的 AI。”

这种做法必然导致**三大致命缺陷**：
1. **“摘要的摘要”严重失真**：总结一次丢一半细节，总结两次关键决策和踩坑记录全变形；
2. **丢失代码现场**：新 AI 不知道本地工作区改动到了哪一步、有哪些未提交的代码、有哪些未解决的报错；
3. **不知道哪些方案走不通**：新 AI 往往兴冲冲地重新尝试上一位 AI 已经验证失败的方案，疯狂重走弯路。

---

## 二、 Handoff 的终极解决方案：Git 原生事件溯源

`handoff` 的一句话定义是：
> **「把一次 Agent 会话封存成一个编号，换任何 Agent、开任何新会话，输入编号接着干。」**

### 1. 零基础设施，Git 即数据库
- 所有的交接快照、现场代码切片与认领记录，都存储在代码仓库自身的专用 Git 引用空间中：
  - `refs/handoff/seal/<编号>`：不可变的交接包 Commit；
  - `refs/handoff/wip/<编号>`：封存瞬间的未提交改动快照；
  - `refs/handoff/claim/<编号>`：认领记录。
- **绝不污染主干分支**：不会产生奇怪的临时 Commit，对正式代码树绝对无害。

### 2. 结构化交接协议 (Contract)
交接包包含且仅包含以下硬核信息：
- **Goal（核心目标）**：本阶段要达成的具体任务与完成标准；
- **Verified Facts（已证实事实）**：经过测试或运行验证的确凿信息；
- **Rejected Hypotheses（已否决弯路）**：尝试过但失败的方案及其原因（**防止后人重蹈覆辙，宁多勿漏**）；
- **Next Step（立即下一步）**：接班人**不需要读其他背景，拿起来就能立刻执行的第一步**。

## 三、 实战操作指南 (手把手教学)

### 场景 A：会话快满了 / 准备下班 / 想换个更强模型接手

1. **在当前 Agent 窗口输入**：
   ```text
   /handoff
   ```
2. **Agent 自动执行**：
   - 提取你在这个会话说过的原话与 Git 提交账本；
   - 归纳生成 `brief.md`（项目提示词）和 `state.md`（动态状态）；
   - 输出封存编号，例如：
     > *已封存 #7 · myapp · 下一步：实现 refresh-token 轮换*
     > *接手方式：输入 /handoff 7*

### 场景 B：开启全新窗口接班

1. **打开全新终端或换成另一个 Agent（如从 Claude Code 切换到 Codex）**；
2. **直接输入**：
   ```text
   /handoff 7
   ```
3. **新 Agent 表现**：
   - 秒级拉取 `#7` 号快照与代码现场；
   - 立即输出三行状态：载入了什么、现场如何、从哪一步开始；
   - **无需你做任何解释，直接自动开始写下一步代码！**

---

## 四、 进阶黑科技：多 Agent 并行物理泳道 (Parallel Lanes)

如果你希望**两个 Agent 同时开发两个不同功能**：
1. 封存前在草稿中创建 `fork.md`，定义两条 lane（如 `lane/auth` 和 `lane/ui`）；
2. 两个 Agent 在各自的独立工作目录（基于 Git Worktree）下认领作业；
3. 开发完成后，运行 `/handoff join 7` 自动汇合分支，解决冲突并合并！
