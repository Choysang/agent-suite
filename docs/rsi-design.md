# 经验闭环升级：设计依据与规范调整

## 目标与边界

将用户提出的六模块 RSI 方案落成可追溯、版本绑定、兼容现有卡片的改进闭环。源码仓库维护可分享的机制，个人 vault 保存私有记录。全局规则只保留入口，细节在 [知识治理协议](../knowledge/RSI.md)。

## 对原提案的调整

| 原提案 | 实施选择 | 原因 |
|---|---|---|
| 新增 type/id/triggers 必填 | 保留 kind、文件名 id、when；triggers 可选 | 避免双份字段与全库迁移 |
| 每次反馈增加 retrieved_count | 计数实际反馈，不伪装曝光统计 | 检索命中不等于采用，更不等于有效 |
| 累计 +3 自动验证 | 版本绑定的三个独立任务 + 证据 + 显式复核 | 限制重复刷分、旧版本信用与自我确认偏差 |
| 分数小于 0 才隔离 | 当前版本有反例立即隔离，修复后重新评估 | 旧成功不能抵消关键失败 |
| 高分卡压过其他结果 | 相关度优先，反馈仅作同分辅助 | 避免流行度循环强化、不相关高分挤占上下文 |
| 红线只增不删、强制统一三节 | 当前方案原地更新，护栏可退役留痕；档案保留八节 | 硬性只增仍会膨胀，八节已承担项目约束与资产 |
| 每次异常立即写知识库 | 项目即时记摩擦，确认可复用后沉淀 | 保留负例而不把瞬时环境故障污染全局 |
| 反馈未做禁止沉淀/交接 | 有结果才结算，缺证据记待定 | 避免为了完成流程伪造分数或阻塞交接 |
| 行数硬限制 | 行数 + 字符数，旧卡逐步接入 | 防止单行超长，保留现有知识可用性 |
| handoff 自动提取工具报错 | 显式记录原始日志定位，内核保持用户原话采集 | 现有适配器并未保存全部工具轨迹 |

## 研究依据及适用限度

- [ModularRSI](https://arxiv.org/abs/2609.14857)：摘要强调模块化修改、成功/失败轨迹对照，以及与评测分离的改进任务。这里据此限制修改范围并保留反例；不把它等同于笔记三段式模板。
- [RRSI](https://arxiv.org/abs/2609.24972)：全称为 Regularized Recursive Self-Improvement，强调限制候选修改、批评和剪枝、检查分布外效果。原提案的 Rapid RSI 命名不准确。
- [Dream-RSI](https://arxiv.org/abs/2609.14858)：利用历史发现树构造回放环境优化探索策略。本仓库固定检索夹具只是确定性回归，不是该论文的模拟环境或复现。
- [Darwin Gödel Machine 作者仓库](https://github.com/jennyzzt/dgm)：代码自修改通过实际编码基准评价。本次用功能检查与独立任务验收约束规则/脚本晋升，不把 LLM 自评分当作能力提升证明。

前三项依据为论文摘要层核对；本实现借鉴工程原则，不声称复现论文或继承其实验收益。

## 模块与验证

| 模块 | 改动 | 验证 |
|---|---|---|
| Templates | 可选治理字段、正文预算、当前方案与历史分离 | 模板 lint、旧卡兼容用例 |
| kb | 分项检索、read / feedback / lint，纯函数治理模块 | Python 测试与固定查询夹具 |
| capture / sink | 负例采集、真实采用反馈、原地整合 | 与 CLI 契约逐项核对 |
| tidy | 退役复核、规则/脚本晋升提案 | 不自动删卡或提权；验收与回滚需明确 |
| handoff | v2 可选投影，引用版本与异常出处 | 保留 v1 必填结构，内核/架构测试与类型检查 |
| guidelines | 三阶段简短入口，中英文同步 | 内容一致性与实际安装路径检查 |

检索相关性、用例成功和自改进收益是三个不同层次。功能测试通过只能确认机制按契约运行，长期效用需要真实、独立任务数据。
